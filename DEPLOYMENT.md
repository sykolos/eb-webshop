# ebtest deployment

GitHub Actions deploys pushes to `develop`.

Configure these GitHub repository secrets:

| Setting | Value |
| --- | --- |
| `DEPLOY_PATH` | `/home/dekorhu/ebtest/myapp` |
| `PUBLIC_PATH` | `/home/dekorhu/ebtest/public_html` |
| `ENV_DEVELOP` | Complete test environment file, including the existing valid APP_KEY and test database credentials |

Keep the existing `SSS_HOST`, `SSH_USER`, `SSH_PORT`, and `SSH_PASSWORD` secrets.
The cPanel document root for `ebtest.dekor26.hu` must be
`/home/dekorhu/ebtest/public_html`.

```text
/home/dekorhu/ebtest/
  myapp/
    .env
    artisan
    app/
    bootstrap/
    config/
    resources/
    routes/
    storage/
    vendor/
  public_html/
    .htaccess
    .laravel-path.php  (generated by the build, points to DEPLOY_PATH)
    index.php
    build/
    storage -> ../myapp/storage/app/public
```

The public entry point reads the generated path, so Artisan and HTTP requests
use the same installation even if older Laravel files remain in the parent
directory. Without a generated path file, local development keeps using the
normal `public/` layout. A broken explicit path fails instead of selecting an
old installation.

The deploy preserves an existing `myapp/.env`. Only when it is absent does it
install `ENV_DEVELOP`. Editing the secret does not replace an existing server
environment file. Do not generate a new APP_KEY for an existing installation.
Preserve the key and uploaded data that belong to this test installation.

Older files in `/home/dekorhu/ebtest` are not removed automatically. Back them
up and identify any needed environment files or uploads before retiring them.
Neither old root storage nor an existing real `public_html/storage` directory
is automatically migrated into `myapp/storage`.

The CLI deployment check validates the public application path, APP_KEY,
required routes, views and writable runtime directories. Migrations run in
`DEPLOY_PATH`. The final HTTP check requests `/`, `/contact`, and `/login`;
an HTTP 500 fails the deployment even if Artisan succeeded.

For HTTP 500 errors, inspect the latest exception in
`/home/dekorhu/ebtest/myapp/storage/logs/laravel.log`, or the dated Laravel log
if configured for daily logging. If no exception is logged there, inspect the
cPanel PHP error log. PHP CLI checks cannot verify the web process's PHP
version, permissions, or the cPanel document root. Keep APP_DEBUG disabled on
the public site. Remove passwords, tokens and personal data before sharing logs.
